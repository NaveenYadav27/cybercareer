■ HARDWARE REQUIREMENTS & ARCHITECTURE DEEP DIVE
CORE CONCEPTS FOR HYPERVISOR WORKSTATIONS
CPU EXTENSION CRITICAL

Hardware Virtualization (VT-x / AMD-V)

What it is: Dedicated hardware instructions built directly into CPU silicon (Intel VT-x / AMD SVM) providing VMX root and non-root operational modes (Ring -1).

Why it matters for VAPT: Allows VirtualBox to execute guest kernel code directly on physical processor pipelines with hardware-assisted memory translation (SLAT/EPT). Without VT-x enabled in BIOS, 64-bit Kali Linux VMs cannot boot.

✓ Direct Ring 0 Execution · Zero Trap Overhead
COMPUTE UNITS SCHEDULING

Physical Cores vs. Logical Threads (SMT)

Physical Cores: Independent physical silicon execution units that execute machine instructions simultaneously.

Logical Threads (SMT/Hyper-Threading): Duplicates processor architectural state so 1 physical core handles 2 instruction pipelines. Hypervisors schedule vCPUs onto these threads.

★ Rule: Allocate max 2 vCPUs per VM to prevent host starvation
VOLATILE MEMORY LATENCY

Physical RAM & Swap Thrashing Risk

vRAM Allocation: The physical memory locked by the hypervisor for guest OS page tables and running services.

Swap Paging Risk: If total VM + host memory exceeds physical RAM, the OS pages memory blocks to storage. If this occurs during an Nmap scan or exploit compilation, the system suffers severe latency freezes.

★ 16 GB Physical RAM ensures 100% in-memory execution
STORAGE BUS RECOMMENDED ★

NVMe PCIe M.2 Storage

What it is: Solid-state storage communicating directly over PCIe lanes with 64,000 parallel command queues (vs 1 queue in legacy AHCI SATA).

Performance: 3,500–7,000+ MB/s sequential transfer with 500,000+ IOPS. Virtual machines boot in under 6 seconds with instant snapshot reversion.

✓ Ultra-low latency (<10µs) · Zero Parallel VM Disk Contention
IOPS BOTTLENECK LEGACY

SATA SSD vs. Mechanical HDD

SATA SSD: Capped at SATA 3.0 limits (~550 MB/s, ~80,000 IOPS). Sufficient for 1-2 VMs running sequentially.

Mechanical HDD (Caution): 80–140 MB/s with only ~100 IOPS. Physical read/write heads thrash when multiple VMs perform random I/O, leading to complete desktop freezes.

⚠ Avoid spinning HDDs for multi-VM penetration test ranges
VIRTUAL DISK FORMAT SPARSE VDI

Dynamically Allocated VDI Storage

How it works: A sparse Virtual Disk Image (VDI) initially occupies minimal host storage (~2 MB) and expands dynamically only as the guest OS writes new blocks up to its configured ceiling.

Best Practice: Configure a 40–80 GB dynamic VDI ceiling for Kali so tool installations (e.g. wordlists, Metasploit, Burp Suite) have room to expand without consuming unnecessary host storage upfront.

✓ Efficient disk footprint + Instant Snapshot copy-on-write
